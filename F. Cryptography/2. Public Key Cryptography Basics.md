
## Introduction 
| Security Goal       | Real-World Example                                    | Cyber-World Problem                                                     |
| ------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------- |
| **Authentication**  | You see/hear the person → confirm their identity      | How do you know the texter is who they claim to be?                     |
| **Authenticity**    | You know the words come from your partner, not others | How do you verify the message genuinely came from the claimed sender?   |
| **Integrity**       | Nothing changes their words across the table          | How do you ensure data wasn't altered while travelling across networks? |
| **Confidentiality** | Low voice, private seating → only they hear you       | How do you stop unauthorized parties from eavesdropping?                |

###### Cryptography Solutions 
| Type           | Key Name                 | Primary Role                                                                  |
| -------------- | ------------------------ | ----------------------------------------------------------------------------- |
| **Symmetric**  | Private Key Cryptography | Confidentiality (encrypting data)                                             |
| **Asymmetric** | Public Key Cryptography  | Authentication, Authenticity, Integrity (verifying identity & unaltered data) |


## Common use of Asymmetric Encryption 
| Analogy     | Cryptographic System              |
| ----------- | --------------------------------- |
| Secret Code | Symmetric Encryption Cipher & Key |
| Lock        | Public Key                        |
| Lock's Key  | Private Key                       |
**How it works:**
1. Ask friend for their lock (public key).
    
2. Put the secret code (symmetric key) in an indestructible box and lock it with their lock.
    
3. Send the locked box over the open.
    
4. Only friend can unlock it with their private key.
    
5. Now both can share the secret code and can communicate privately at high speed


### RSA ( Rivest–Shamir–Adleman )
- asymmetric/public-key cryptography 
- keys 
    - public key ( n, e ) → encryption 
    - Private Key ( n, d ) → decryption 
    - public key can be shared and private key must protected.

###### Important Variables;
|Variable|Meaning|
|---|---|
|`p, q`|Large prime numbers|
|`n`|`p × q`|
|`φ(n)`|`(p−1)(q−1)`|
|`e`|Public exponent|
|`d`|Private exponent|
|`m`|Plaintext/message|
|`c`|Ciphertext|
###### Formula;
```
n = p × q

φ(n) = (p−1)(q−1)

Encryption:
c = m^e mod n

Decryption:
m = c^d mod n

e × d ≡ 1 mod φ(n)
```



### Diffie-Hellman Key Exchange 
- key exchange method used to create a shared secret over an insecure network 

###### Example;
Alice and Bob never send the shared secret Directly.
```
Public: p, g
       ↓
Alice chooses private a
Bob chooses private b
       ↓
Alice: A = g^a mod p
Bob:   B = g^b mod p
       ↓
Exchange A and B
       ↓
Alice: Secret = B^a mod p
Bob:   Secret = A^b mod p
       ↓
Same shared secret
```

***Variables from the above Example***;

|Variable|Meaning|
|---|---|
|`p`|Large prime|
|`g`|Generator|
|`a`|Alice's private key|
|`b`|Bob's private key|
|`A`|Alice's public key|
|`B`|Bob's public key|
###### Formula
```
A = g^a mod p
B = g^b mod p

Shared Secret:
B^a mod p = A^b mod p

= g^(ab) mod p
```

#### Cyber security Used;
- secure key agreement
- establishing session keys over insecure networks
- used in protocols such as TLS, VPNs, SSH, ETC
- combined with authentication to prevent **MITM** ATTACKS.



### SSH  ( Secure Shell )
- secure protocol for remote login and administration 
```
Client  ───── encrypted connection ─────>  Server
```
- uses encryption + authentication to protect the connection 

#### Server Authentication 
- while, connecting for the first time;
```
ssh user@host
```

- after, accepting SSH stores the server key in:
```
~/.ssh/known_hosts
```
- If a known server suddenly presents a different key, investigate → possible MITM attack.


#### Client Authentication 
```
username + password 
```
**SSH Key Pair**
```
Public key  → Server
Private key → Your machine
```

- server stored allowed public keys in:
```
~/.ssh/authorized_keys
```
- never share private key 

#### Generate SSH Key 
```
ssh-keygen -t ed25519
```
**Creates**
```
~/.ssh/id_ed25519       ← PRIVATE KEY  → never share 
~/.ssh/id_ed25519.pub   ← PUBLIC KEY  → safe to give to server
```


#### Login Using Private Key 
```
ssh -i privateKey user@host
```

***Example***;
```
ssh -i id_ed25519 user@10.10.10.10
```
**Private Key Permission**
```
chmod 600 id_ed25519
```


#### Copy Public Key to Server
```
ssh-copy-id user@host
```

This places you public key into:
```
~/.ssh/authorized_keys
```


***IMPORTANT SSH Files;***

| File                     | Purpose                      |
| ------------------------ | ---------------------------- |
| `~/.ssh/id_ed25519`      | Private key                  |
| `~/.ssh/id_ed25519.pub`  | Public key                   |
| `~/.ssh/authorized_keys` | Public keys allowed to login |
| `~/.ssh/known_hosts`     | Server keys/fingerprints     |

### Digital Signatures & Certificates 
   ##### Digital Signature
- Digital signature verifies 
    - Authenticity → who signed it?
    - Integrity → was it changed?
    - Non-repudiation → signer cannot easily deny signing it.

***How it works***
```
Document
   ↓
Hash
   ↓
Sign hash with PRIVATE KEY
   ↓
Digital Signature
```
   ***Receiver***
```
   Received Document → Hash it
                         ↓
Signature → Verify with PUBLIC KEY
                         ↓
                 Hashes match?
                    ↓       ↓
                   YES      NO
                  Valid   Modified
```
 - Private key → sign
 - Public Key → verify


##### Digital Certificate 
- helps to prove that a public key belongs to a particular identity or domain

*Example;* 
```
You visit:
https://tryhackme.com
        ↓
Server sends certificate
        ↓
Browser checks certificate
        ↓
Trusted CA?
        ↓
Domain matches?
        ↓
Certificate valid?
        ↓
🔒 Trusted HTTPS connection
```

##### Certificate Authority ( CA )
- trusted organization that issues/signs certificates 
```
Root CA
   ↓
Intermediate CA
   ↓
Website Certificate
   ↓
Website Public Key
```
- called as a chain of trust 

## Cyber security Work 
```
Digital Signature
→ Private key signs
→ Public key verifies
→ Hash ensures integrity

Certificate
→ Binds identity/domain + public key
→ CA provides trust
→ Used in HTTPS/TLS

CA
→ Trusted authority
→ Issues/signs certificates
```

##### Digital Signature VS Certificate 

|Digital Signature|Certificate|
|---|---|
|Proves a message/file was signed|Links identity to a public key|
|Uses private key to sign|Issued/signed by a CA|
|Public key verifies signature|Used heavily in HTTPS/TLS|
|Protects integrity/authenticity|Establishes trust|



### PGP & GPG
- **PGP** → Pretty Good Privacy 
- **GPG ( GnuPG )** → open-source implementation of the OpenPGP standard.
- Used for;
    - Encryption/ decryption 
    - digital signatures
    - secure email/file communication 

***Key Concept***
```
Sender
   ↓
Encrypt with YOUR public key
   ↓
Encrypted message
   ↓
Decrypt with YOUR private key
```

#### Important GPG Commands 
1. Generate a key pair 
```
gpg --full-gen-key
```
- creates a public + private key 

2. List Keys 
```
gpg --list-keys
```

3. Import a Key 
```
gpg --import backup.key
```

4. Decrypt a File 
```
gpg --decrypt confidential_message.gpg
```

5. Export Public Key 
```
gpg --export --armor email@example.com > public.key
```

##### CTF/ Cybersecurity Importance 
- may receive 
```
private.key
encrypted.gpg
```
- typical process 
```
Import key
   ↓
gpg --import key
   ↓
Decrypt file
   ↓
gpg --decrypt file.gpg
   ↓
Read flag
```

If GPG private key is protected by a passphrase tools 
- gpg2john
- John the Ripper
**can be  used as a paraphrase recovery**.
