### TCP/IP Model 

- **Application Layer** → OSI Layers **5, 6 & 7** combined; provides network services to applications.
- **Transport Layer** → OSI Layer **4**; provides end-to-end communication. **TCP, UDP**
- **Internet Layer** → OSI Layer **3**; handles IP addressing and routing. **IP, ICMP**
- **Link Layer** → OSI Layer **2**; handles local network communication. **Ethernet, Wi-Fi**
- **Physical Layer** → OSI Layer **1**; handles transmission of raw signals. **Electrical, optical, wireless**


|OSI|TCP/IP|Examples|
|--:|---|---|
|7, 6, 5|**Application**|HTTP, DNS, FTP, SSH|
|4|**Transport**|TCP, UDP|
|3|**Internet/Network**|IP, ICMP|
|2|**Link**|Ethernet, Wi-Fi|
|1|**Physical**|Electrical, Optical, Wireless|


### IP Address and Subnets 

###### IPV4 Address 
- 32 bits long 
- divide 4 octets
- each octet = 8 bits 
- each octet value from 0-255

### UDP and TCP 

**UDP = Fast, no guarantee**  
**TCP = Reliable, connection required**

| **Feature**        | **UDP**                       | **TCP**                       |
| ------------------ | ----------------------------- | ----------------------------- |
| **Full Name**      | User Datagram Protocol        | Transmission Control Protocol |
| **Layer**          | Layer 4 (Transport)           | Layer 4 (Transport)           |
| **Connection**     | Connectionless                | Connection-oriented           |
| **Reliability**    | No delivery confirmation      | Reliable delivery             |
| **Speed**          | Faster                        | Slower than UDP               |
| **Ordering**       | No guaranteed order           | Maintains correct order       |
| **Acknowledgment** | No                            |  Yes                          |
| **Use**            | Speed-sensitive communication | Reliable data transfer        |


**PORT Number = 16 bits ---> 1-65535, port 0 is reserved**

**TCP 3-WAY Handshake**
- SYN → client request connection 
- SYN-ACK  → Server acknowledges and responds 
- ACK → client acknowledges → connection established 



### Encapsulation 

- each network layer adds its own header and sometimes trailer to the data before passing to the next layer 

###### Data changes as it moves down 
|Layer|What Happens|Data Unit|
|---|---|---|
|**Application**|Creates the original data|**Data**|
|**Transport**|Adds TCP/UDP header|**Segment / Datagram**|
|**Network**|Adds IP header|**Packet**|
|**Data Link**|Adds header + trailer|**Frame**|
Data → Segment → Packet → Frame
**Decapsulation**
Frame → Packet → Segment → Data

 ==While visiting TryHackMe==
 - enter a search query → Application Data
 - TCP adds header → TCP segment
 - IP adds source and destination IP →IP Packet 
 - Ethernet/Wi-Fi adds header + trailer → Frame
 - frame travels through the network 
 - receivers remove each header and trailer until the original data reaches application
